# SO-101 Pi0.5 JAX fine-tuning

Two independent OpenPI configs are provided for the blue-pen comparison:

| Config | Local dataset | Episodes | Frames |
|---|---|---:|---:|
| `pi05_so101_60` | `/mnt/pqssd/so101/datasets/merged_grab_blue_pen_60` | 60 | 10,559 |
| `pi05_so101_90` | `/mnt/pqssd/so101/datasets/merged_lerobot_dataset_with_dagger30_trimmed` | 90 | 17,391 |

Both runs use 30 Hz LeRobot v3 data, `front` and `wrist` RGB, six absolute motor-position targets, a 50-step action
horizon, and the same Pi0.5 JAX base. The six state/action values are padded to the model's 32-dimensional internal
space. `front` maps to `base_0_rgb`, `wrist` maps to `right_wrist_0_rgb`, and the unused left-wrist slot is masked.

“Train both from scratch” should mean two independent fine-tunes initialized from the same pretrained Pi0.5 base, not
random model initialization and not continuing the 90-episode run from the 60-episode checkpoint.

## Local preflight

Use the locked LeRobot environment. The commands below retain the required BFSU PyPI mirror:

```bash
cd /home/larry/openpi-kuavo
export UV_DEFAULT_INDEX=https://mirrors.bfsu.edu.cn/pypi/web/simple
export OPENPI_DATA_HOME=/tmp/openpi-data

uv run scripts/smoke_test_so101_dataset.py --config-name pi05_so101_60
uv run scripts/smoke_test_so101_dataset.py --config-name pi05_so101_90
```

The smoke test prints the imported LeRobot module path. Stop if it resolves to an unrelated editable checkout instead of
the commit locked by this repository.

## Compute full normalization statistics

Each comparison requires its own statistics:

```bash
uv run scripts/compute_norm_stats.py --config-name pi05_so101_60 --batch-size 32 --num-workers 8
uv run scripts/compute_norm_stats.py --config-name pi05_so101_90 --batch-size 32 --num-workers 8
```

Expected outputs are:

```text
assets/pi05_so101_60/so101_grab_blue_pen_60/norm_stats.json
assets/pi05_so101_90/so101_grab_blue_pen_90/norm_stats.json
```

Do not reuse the 60-episode statistics for the 90-episode run.

## Independent training runs

After a real one-batch/10-step GPU smoke succeeds, start each production run with a distinct experiment name and
checkpoint directory:

```bash
uv run scripts/train.py pi05_so101_60 --exp-name so101_60_base_v1
uv run scripts/train.py pi05_so101_90 --exp-name so101_90_base_v1
```

The checked-in defaults are conservative local values (`batch_size=1`, W&B disabled). On Vast, use
`scripts/vast/run_pi05_pipeline.sh` with `ROBOT_TASK=so101_60` or `ROBOT_TASK=so101_90`, explicitly set each private
model repository, and probe the global batch size before a full run. The dataset defaults are
`larryi/so101_grab_blue_pen_60` and `larryi/so101_grab_blue_pen_90`.

## JAX inference and robot boundary

A trained Orbax checkpoint can be served directly without conversion:

```bash
uv run scripts/serve_policy.py policy:checkpoint \
  --policy.config=pi05_so101_60 \
  --policy.dir=checkpoints/pi05_so101_60/so101_60_base_v1/30000
```

The inference request must contain `observation.images.front`, `observation.images.wrist`, a six-element
`observation.state`, and `prompt`. The response is `actions` with shape `(50, 6)` in the dataset's absolute SO-101 motor
position space. Add joint-limit checks, rate limiting, action-chunk execution policy, and an emergency stop in the robot
client before hardware tests.

JAX-to-PyTorch checkpoint conversion is a separate deployment gate. The OpenPI converter should not be assumed valid for
this SO-101 checkpoint until its output is numerically compared against JAX inference on identical observations.
